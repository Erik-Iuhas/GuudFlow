# Design Decisions Log

One-line entries. Log when a structural decision is made that isn't obvious from the code.

- 2026-04-25 — strict protocol parser over lenient (DESIGN §18 — mis-parses are worse than failures; bad-faith outputs detected by downstream review, not by silently coerced parsing)
- 2026-04-25 — protocol ASK/ANSWER parser accepts both `→` and `->` (defensive against arrow-character loss in copy/paste; render still uses `→`)
- 2026-04-25 — VerifyResult FAIL-without-detail validation in `__post_init__` (DESIGN §18 makes this a hard rule; enforce at construction so render_verify cannot produce invalid output)
- 2026-04-25 — tracker location: project-local `.claude/progress/`, committed to git (user choice)
- 2026-04-25 — `Workspace.files` typed as forward-ref `"FileWorkspace | None"` so workspace.py can be unit-tested without filesystem and avoids a circular import
- 2026-04-25 — `GitWorkspace` takes a callback `Callable[[SignalType, str, str|None], None]` instead of importing `Signal` directly — keeps the git module decoupled from board management
- 2026-04-25 — context_manager `_score_entry` returns 0 (not PageRank tiebreak) when query has terms but no token overlap — otherwise unrelated searches get false positives
- 2026-04-25 — context_manager `_tokens` produces both whole-identifier and camel/snake-split components, applied to both query and symbols, so `AuthManager` matches `AuthManager` regardless of which side is split
- 2026-04-25 — added DESIGN §30 (Credentials Broker / RBAC) before Stage 3. Pattern parallels IT agent: event-driven gatekeeper agent, default-deny RBAC, broker proxies credentialed calls so agents never hold tokens. Three new signal types added to signals.py (CREDENTIAL_REQUEST/GRANTED/DENIED). BaseAgent helpers `request_credential()` / `invoke_mcp()` land Stage 4; broker agent itself lands Stage 5 (can ship as deny-everything stub initially).
- 2026-04-25 — scheduler human-pause uses an external `notify()` call rather than embedding asyncio primitives in Workspace. Workspace stays a pure data structure; the Stage 5 runner will wrap `post_signal` to call `scheduler.notify()` on HUMAN_RESPONDED. Tests call `notify()` directly.
- 2026-04-25 — paused agents use a re-spawn pattern (return from runner, scheduler respawns when pending_human clears) instead of awaiting an event inside the runner. Keeps the agent runner contract synchronous-on-completion and avoids leaking scheduler internals into the agent.
- 2026-04-25 — `MAX_ITERATIONS` triggers when any single role's spawn count hits the cap without completing. This is per-role, not global, because the natural failure mode is one stuck agent rather than an overloaded run.
- 2026-04-25 — added DESIGN §31 (Tool System), §32 (File Coordination), §33 (Run Initialization) before Stage 4 starts. Three new signal types added to signals.py: `FILE_CLAIM`, `FILE_RELEASE`, `MANIFEST_INVALIDATED`. Stage 4 will implement BaseAgent's `call_tool`, claim helpers, and the namespaced built-in catalog (read tools first, write tools after broker stub). Run initialization (clone, seed, README.md) is a Stage 5 runner concern.
- 2026-04-25 — built-in tools normalized to namespaced names (`fs:read`, `doc:pdf`, etc.) to match the MCP `mcp:server:tool` convention. RBAC scope names equal tool names 1:1, so the broker's enforcement code is uniform across local and MCP tools.
- 2026-04-25 — file claims are advisory + automatic at the tool layer rather than enforced locks. Rationale: branch-per-agent (§19) already provides data safety; the gap is *effort coordination*. Locks would add complexity for no additional safety. Default-wait behaviour gives a sane default; agents can override with reasoning if needed.
- 2026-04-25 — `inputs/` made strictly read-only at runtime. Continuation runs preserve persona memory but start fresh git history in `working/` (prior history archived as a bundle). This avoids the "two timelines diverge" problem when a continuation diverges substantially from the prior run.
- 2026-04-25 — added DESIGN §34 (Memory Dynamics) before Stage 4 personas.py is written. Extends §26 with: pattern lifecycle states (emerging→active→declining→archived/superseded), recency-weighted confidence (90d half-life), context-specific narrowing of `applies_when` before global decay, pattern→anti-pattern flipping when declines pair with clear inverse evidence, episode staleness affecting retrieval weight, and an end-of-run reconciliation pass in memory_writer. User overrides (pin/retire/promote) supported but logged. Stage 4's `recall()` reads/filters; Stage 5's memory_writer writes.
- 2026-04-25 — episodes.jsonl remains append-only at data layer; only `staleness` field mutates, via atomic rewrite. No episode is ever deleted — archived patterns and stale episodes are recoverable if new evidence emerges.
- 2026-04-25 — added DESIGN §35 (Training Camp), §36 (Project-Specific Rules), §37 (Chat Endpoint future) before Stage 4 starts. Effective system prompt layer order updated: Layer 3.7 (project rules) inserted between teammate_brief and memory; rules trump memory on conflict. Tool catalog from manifest now appended in Layer 5.
- 2026-04-25 — Training Camp = mode flag on existing run infrastructure, not a separate runner. Episodes feed memory unified; reputation aggregates split production/training. Graduation soft-gates production hires (warning, not block). Smaller-model users compensate via training volume — first-class support.
- 2026-04-25 — Project rules in markdown, project-side storage at `data/projects/{id}/persona_rules/`. `_shared.md` for cross-persona project-wide rules + per-persona overlays. Auto-suggestion from feedback proposes rule additions but NEVER auto-applies — invisible state mutation is anti-feature. Rules trump memory on conflict via prompt layer ordering.
- 2026-04-25 — Chat endpoint marked future/optional, post-MVP. Spec'd now to avoid awkward retrofit. Read-only by default; no broker/MCP access; rate-limited; audit-logged. A thin shell over `recall()` + single LLM call.
- 2026-04-25 — Stage 4 chunked into persona → tool infrastructure → tools → BaseAgent → registry; each chunk shipped with passing tests before moving on. Persona built first since BaseAgent depends on it; broker stub built before BaseAgent so `request_credential` had a real target.
- 2026-04-25 — `AntiPattern` and `Pattern` share the lifecycle/confidence interface (lifetime_applications, applications window) so a single `compute_confidence` handles both. Anti-patterns also age via recency weighting — symmetric with patterns.
- 2026-04-25 — `fs:edit` defaults to single-match (errors on 0 or 2+). `replace_all=true` is required to touch multiple occurrences. Prevents accidental whole-file rewrites and surfaces ambiguity to the agent.
- 2026-04-25 — Tool tests use injectable handlers (web/code) rather than real network/subprocess calls. Production wiring overrides without changing the BaseTool contract.
- 2026-04-25 — All write-side fs tools take optional claim_emitter/release_emitter callbacks. BaseAgent will wire these to its own `claim_files`/`release_files` in Stage 5's runner; Stage 4 tests use plain mock callables.
- 2026-04-25 — Added four post-Stage-4 read tools before moving to Stage 5: `fs:read_range`, `fs:grep`, `code:outline`, `git:status`. Reasoning: 1) the `fs:read` → whole-file pattern was the biggest token-efficiency leak in the toolset, and 2) `git:status` plugs an obvious visibility gap (`git:diff` is between branches but agents had no way to see uncommitted state on their own branch). All four are baseline scopes — read-only, no RBAC declaration needed.
- 2026-04-25 — `fs:grep` is pure-Python (no ripgrep dependency). Skips a small set of binary extensions (.png, .pdf, .zip, etc.) to avoid noise. Defaults to literal text + case-insensitive (most common case); `regex=true` and `case_sensitive=true` opt in. Returns `before`/`after` context lines per match.
- 2026-04-25 — `code:outline` reuses the tree-sitter grammars already loaded by `core/repo_map.py` but writes a more-detailed walker (methods within classes, signatures with params). Stage 5's reviewer agent will use this heavily on iteration ≥ 2 to navigate without re-reading whole files.
- 2026-04-25 — Added 9 general-purpose tools post-Stage-4: `text:diff`, `text:estimate_tokens`, `data:json`, `data:csv`, `data:yaml`, `data:xml`, `time:now`, `time:diff`, `math:eval`. All baseline scopes (read-only/pure). PyYAML and defusedxml added to requirements; defusedxml chosen specifically for XXE safety. `math:eval` uses AST-allowlist evaluator (no `eval()`, no name lookups, no function calls); also rejects booleans and strings to keep the surface strictly numeric.
- 2026-04-25 — `data:json`'s `json_path` accepts both array form (unambiguous, supports dots/slashes in keys like OpenAPI paths) and dot-string form (convenient for simple cases). Numeric strings in dot-paths auto-convert to int indices.
- 2026-04-25 — `data:xml` enforces a default `max_depth` of 8 with `children_truncated` markers past that. Prevents context blowups on deeply-nested XML and enforces "ask for more" pattern.
- 2026-04-25 — Hardened dev-mode `code:exec` before adding the general tools: mode enforcement (AGENTFLOW_MODE=production refuses host runner), per-run quota (default 50), audit log with code preview truncation, env scrubbing (curated allowlist + secret-name double-check), CWD pinning, POSIX rlimits. Container is still the real production answer (Stage 7); the dev hardening narrows the gap.
- 2026-04-25 — Tool files renamed to avoid stdlib shadow: `time_tool.py` (not `time.py`) and `math_tool.py` (not `math.py`). Tool name strings are unchanged (`time:now`, `math:eval`).
- 2026-04-25 — Stage 5 runner uses an injectable `agent_factory` so prompt-defined agents (BaseAgent + system_prompt) and registered builtins (CodeReviewer, ITAgent, etc.) share one orchestration path. Subclasses override `run()` for custom behavior; default agents fall through to a generic tool-use loop driven by the runner.
- 2026-04-25 — Memory_writer's reconciliation order: contradictions FIRST, then lifecycle transitions. Otherwise a soon-to-decline pattern drops out of ACTIVE before the contradiction check fires and never gets formally superseded. Persistence requires `persona._dir` set by the runner — runtime convention, not a profile field.
- 2026-04-25 — `credentials_broker` builtin agent deliberately not added in Stage 5. `core/credentials_broker.py` provides the broker as a class with handler registration (simpler than event-driven). The §30 "agent" framing collapses to broker-as-class; this redesign is documented in stage-5-runner.md notes. Reconsider if Stage 6 surfaces a need.
- 2026-04-25 — Quip engine fails gracefully — if the LLM call raises, log records "(quip failed: ...)" rather than propagating. Quips are flavour, not load-bearing for the run.
- 2026-04-25 — Added `OpenAIClient` adapter to `core/llm.py` for OpenAI-compatible inference servers (OpenAI, Ollama, LM Studio, vLLM, OpenRouter, llamafile). Critical for the §35 smaller-model story — those users overwhelmingly run Ollama or local servers. Internal message format stays Anthropic-shaped (content blocks); the adapter translates at the wire boundary (assistant tool_calls, role=tool messages for results, JSON-string arguments). Convenience factories `ollama()` and `openai_compatible()` for common setups. Note: prompt-based tool calling for models without function-calling support is NOT yet wired — current adapter assumes the server supports OpenAI tool spec (modern Ollama qwen2.5/llama3.1/mistral-small all do).
- 2026-04-25 — Stage 6 API uses `Body(...)` defaults on dict params (FastAPI otherwise treats the parameter name as a wrapping key). The auth dependency `require_bearer` MUST use `Depends(_bearer_scheme)` for `HTTPAuthorizationCredentials` — without it, FastAPI parses the dep function's signature as if it were a route signature and breaks every protected route's body parsing. This was a real loop-into-the-door for ~5 dev iterations; logged here so the next session doesn't repeat it.
- 2026-04-25 — WebSocket live-stream handler races `queue.get()` against `websocket.receive()` so a client disconnect breaks the server out of waiting on its own queue. Without this, the handler hangs forever on disconnect. The receive task is a single call, not a loop — once a disconnect message arrives starlette refuses further `receive()` calls.
- 2026-04-25 — Added `core/loop_guard.py`: per-agent-attempt LoopGuard with three signals (wall-clock deadline → abort, repeated identical (name,args,error) → nudge, alternating cycle → nudge, repeated error class → nudge). Runner injects nudges as `[LOOP GUARD]` user messages before the next LLM turn — the LLM gets an explicit "stop doing that, try something else" rather than just re-seeing the same tool error. Added `Workspace.deadline_at` + `SchedulerStatus.DEADLINE_EXCEEDED` for run-level wall-clock budget enforced by the scheduler.
- 2026-04-25 — LoopGuard nudges fire BEFORE iteration cap. Without the nudge a model would just retry blindly until it hit `max_tool_iterations` and got a generic "max iterations" message. With the nudge, the model has a real chance to course-correct mid-attempt. The nudge lifecycle is: detected by guard → appended to user turn as `[LOOP GUARD] ...` → cleared after delivery so the same nudge doesn't keep re-appearing.
- 2026-04-26 — Phase D continuation flow uses "option B" — when the user approves a delta proposal in Propose.tsx, the studio PUTs the entire updated team config back to the project, overwriting the prior team's `agents` field. The runner then just uses the updated config; there is no separate per-run delta record. Trade-off: delta history is lost once approved (the project's stored config no longer reflects "what was different about this run"), but the runner stays simple — no special continuation-aware path beyond what D-prime already shipped (inputs seeding from `from_run_*/`). If future audit needs surface, a `data/projects/{id}/run_history/{run_id}.json` snapshot at invoke time would capture the team that ran without changing the runner. Documented to avoid re-litigating the choice.
- 2026-04-26 — MetaAgent uses tool-use (structured `propose_team` schema) over JSON-in-text parsing. Reasoning: tool-use shape is enforced by the Anthropic API; JSON-in-text is brittle (escape errors, trailing commas, model adds explanatory prose around the block). The fallback to a hardcoded skeleton on any LLM failure means `/api/meta/propose` never 500s — degraded responses with `warnings` populated.
- 2026-04-26 — Persona ids embed a human first name: `{name}-{role}-v1` (e.g. `mike-frontend-v1`). The display name (`Mike`) is what shows in quips/UI; the role + version make the id globally unique. Added `used_display_names` parameter to `suggest_persona_id` so a 3-agent team gets 3 different first names rather than 3 Mikes — keeps quip output reading like a real team.
- 2026-04-26 — Worker archetype catalog is split: YAML (`docs/worker-archetypes.yaml`) is canonical for the meta-agent's prompt (compact tokens, structured fields); markdown (`docs/worker-archetypes.md`) is a derivative human-readable view. The runtime catalog (`agents/catalog.list_archetypes()`) covers the 4 shipped concrete classes; `list_all_archetypes()` unions runtime ∪ YAML so the meta-agent can pick from 16 archetypes (4 shipped + 12 described). Described archetypes graduate to shipped in Phase F training-camp work.
